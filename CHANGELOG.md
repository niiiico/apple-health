2026-08-27 - Close the TLS gap on the database connection: the pod now uses `sslmode=verify-full`, which checks the chain and the hostname and so proves which server answered. Yesterday's entry and ADR-006 both said this was blocked on issuing a client certificate — that was wrong, and the correction is the useful part: `verify-full` describes how *this* end verifies the *server* and needs only the root CA, which was already mounted in the pod for oauth2-proxy. A client certificate is the other direction. Conflating them had a real cost, since it made a change that needed nothing look like it needed a passphrase and a maintenance window.
